# Persistent City Generation System

## Purpose

The city is no longer generated by the renderer from the current number of stops.

It is now a persistent simulation layer.

The core rule is:

```text
build transport infrastructure
→ unlock development area
→ reveal a persistent master plan
→ construct local roads over time
→ reserve valid parcels
→ construct individual buildings
→ keep everything permanently in the save
```

A new station increases development opportunity. It does not instantly materialize a finished district.

## State model

The save now contains:

```text
state.city
├── version
├── seed
├── timeSeconds
├── nodes
├── roads
├── districts
├── blocks
├── parcels
├── buildings
├── projects
└── nextProjectId
```

This is simulation state, not renderer state.

The renderer reads it and never decides which buildings exist.

## Deterministic master plan

At city creation, `generateCityMasterPlan(seed)` generates the full latent plan.

The current default seed is:

```text
284731
```

The same seed produces the same:

- district anchors,
- street graph,
- road geometry,
- blocks,
- parcels,
- zoning,
- parcel development ordering,
- street frontage.

The plan is persisted.

Future development changes statuses, not geometry.

## Latent versus built city

A district can contain planned roads and parcels long before the player can see completed buildings.

Typical lifecycle:

```text
LOCKED DISTRICT
    ↓
station purchased
    ↓
ACTIVE DISTRICT
    ↓
local roads queued
    ↓
road construction
    ↓
road built
    ↓
parcel becomes developable
    ↓
building project queued
    ↓
construction site
    ↓
building complete
```

Already completed objects are never repositioned or regenerated when later stations are purchased.

## Road graph

The city master plan currently contains 23 road edges across the complete Bus Era.

Each edge stores:

- stable ID,
- district,
- road class,
- source,
- from/to graph node IDs,
- persistent polyline,
- unlock contract,
- construction state and progress.

Road classes currently include:

- `arterial`
- `local`
- `service`

Primary bus corridors are represented as arterial roads.

When the player purchases the station that requires a corridor, that arterial becomes built immediately so the bus service has a physical road.

Secondary district streets are built gradually.

The Bus Depot access road remains locked until the depot itself exists.

## District activation

The master plan currently contains eight districts:

1. Old Town
2. Market Square
3. City Park
4. University
5. Central
6. Riverside
7. Museum
8. Harbor

A district becomes active when its corresponding transport stop exists.

Activation:

- does not create completed buildings,
- enables its blocks,
- queues its local-road projects,
- starts accumulating development age and pressure.

## Blocks and parcels

Blocks are persistent groups of parcels.

Parcels store:

- stable ID,
- district and block,
- world position,
- footprint,
- frontage size,
- setback,
- zoning,
- density class,
- deterministic development order,
- nearest/frontage road,
- lifecycle status,
- optional building ID.

The complete Bus Era currently resolves to roughly thirty valid parcels for the default seed.

### Plan-time validation

Candidate parcels are rejected before the master plan is finalized if they conflict with:

- any primary arterial,
- any future secondary street,
- any transport stop,
- Bus Depot reserved space,
- another accepted parcel.

This is intentionally done against future infrastructure too.

A building cannot later discover that the future road was supposed to pass through it.

Every accepted parcel also stores `frontageRoadId`, creating the basis for future:

- addresses,
- driveways,
- entrances,
- parking access,
- building-generated car trips.

## Time-based construction

City development uses explicit projects.

A project stores:

- type,
- target,
- district,
- queued time,
- eligibility time,
- start time,
- duration,
- progress,
- completion time.

Only two projects can currently be active globally at the same time.

This prevents an unlocked district from appearing all at once.

### Current early timing

At 1× speed, the starting area behaves approximately like:

```text
0 s      Old Town plan becomes active
5–25 s   local streets are constructed
35–40 s  first building starts construction
~50 s    first building completes
60–90 s  additional individual buildings follow
```

The exact order is deterministic but development speed can later be rebalanced.

## Development pressure

A parcel is not developed only because enough time passed.

District development pressure currently includes:

- district age,
- number of stops on its line,
- recent actual passenger arrivals,
- fleet size,
- interchange bonus,
- central-district bonus.

Conceptually:

```text
development pressure =
    age
  + transport coverage
  + actual ridership
  + service intensity
  + location bonuses
```

This is the foundation for proper transit-oriented development.

A later iteration can extend the same score with:

- population,
- jobs,
- land value,
- road congestion,
- nearby amenities,
- noise,
- accessibility to multiple transport modes.

## Building selection

When a parcel becomes eligible, the city derives a building profile from:

- zoning,
- planned parcel density,
- district type,
- current development pressure.

Examples:

- low residential → house,
- stronger residential → townhouse / apartment,
- mixed → shop / mid-rise,
- central commercial under high pressure → tower,
- civic near University → campus building,
- industrial → workshop / warehouse.

The chosen profile is persisted on the building project.

It is not rerolled by the renderer.

## Construction rendering

The renderer displays the state of the real project.

Building construction visibly progresses through:

- surveyed/fenced parcel,
- foundation,
- structural frame,
- completed building.

Road construction similarly shows:

- planned alignment,
- partially completed road,
- construction head,
- finished street.

This means city growth can be watched in normal gameplay.

## Save migration

Game state is now version 8.

Older Bus Era saves migrate into the new city model.

Migration preserves the transport/economy state and creates a deterministic city master plan consistent with the already unlocked stops.

After migration, future development proceeds normally.

A save/reload round trip preserves the exact city plan.

## Architecture

```text
transportLayout.js
        ↓
planGenerator.js
        ↓
cityModel.js
        ↓
simulation/model.js
        ↓
state.city
        ↓
cityRenderer.js
```

### planGenerator.js

Owns deterministic spatial planning.

### cityModel.js

Owns lifecycle, development pressure, projects and construction timing.

### cityRenderer.js

Only visualizes persistent city state.

It does not create lots or decide which building should exist.

## Current scope

This milestone implements the foundation corresponding to:

1. persistent city state,
2. persistent road graph,
3. latent master plan,
4. planned district roads,
5. blocks and parcels,
6. time-based development.

Still deferred:

- parcel redevelopment,
- actual residents/jobs,
- buildings generating passenger trips,
- dynamic land value,
- road-capacity simulation,
- real car traffic and congestion,
- bus lanes,
- tram rails embedded into road edges,
- automatic procedural expansion beyond the authored Bus Era districts,
- city-generation debug/heat-map UI.

Those should build on the persistent model rather than reintroduce renderer-driven procedural decoration.
