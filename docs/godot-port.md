# Godot Port

## Status

The Godot port is being developed in parallel with the current browser / Three.js build.

The web version remains the gameplay reference until Godot reaches feature parity.

Current Godot milestone:

- Godot 4.6 project,
- deterministic terrain,
- terrain biomes,
- instanced vegetation,
- all four Bus Era route geometries,
- physical shared stations,
- local station levels,
- Bus Depot,
- visible bus vehicles,
- orbit / pan / zoom camera,
- map picking,
- Inspector / HUD,
- core four-line progression rules,
- exact per-passenger origin→destination waiting matrices,
- vehicle dwell / boarding / travel phases,
- onboard passenger loads,
- fare credited only when passengers alight at their destination,
- queue capacity and abandonment,
- canonical 15-district city master-plan fixture generated by the current JS generator,
- persistent district activation,
- road construction projects with parent-road dependencies,
- parcel development pressure,
- building construction projects,
- persistent building height / orientation,
- incremental 3D rendering of city roads, junctions and buildings,
- vegetation clearing around newly occupied roads / parcels,
- native Godot save file containing transport, passengers and city runtime state.

Not yet at parity:

- the procedural master-plan generator itself (Godot currently consumes the canonical JS-generated fixture),
- runtime road-topology generation (junction graph data is already present in the fixture),
- visible waiting passenger objects,
- boarding / alighting visual effects,
- ambient car traffic,
- browser localStorage save import.

## Architecture

The port deliberately keeps simulation state separate from rendering.

```text
GameStore
   ↓
gameplay state / economy / progression
   ↓
TransportLayout + TerrainModel
   ↓
render-only Node3D layers
```

The intended final architecture is:

```text
simulation state
├─ passengers
├─ stations
├─ lines
├─ vehicles
├─ city
├─ roads
├─ parcels
└─ buildings

rendering
├─ terrain
├─ vegetation
├─ roads
├─ stations
├─ buildings
└─ vehicles
```

A renderer should never become the authoritative gameplay state.

## Run

Install Godot 4.6.

From the repository root:

```bash
godot --path godot
```

or open:

```text
godot/project.godot
```

in the editor.

The project has no third-party Godot addons.

## Headless self-test

```bash
godot --headless --path godot --script res://scripts/debug/self_test.gd
```

The current self-test validates:

- shared physical interchanges,
- all four route geometries,
- real-world stop spacing for Lines 3 and 4,
- deterministic terrain,
- sane slope / forest samples.

## Controls

- left mouse drag — orbit,
- right mouse drag — pan,
- mouse wheel — zoom,
- F — reset camera,
- Space — pause / resume,
- click a station — inspect / upgrade,
- click a ghost stop — extend its line,
- click a ghost new-line branch — open that line,
- click the Bus Depot — buy buses / expand garage.

## Save format

The initial Godot port writes:

```text
user://save_godot_v2.json
```

This is intentionally separate from the browser localStorage save.

The schema stores:

- money,
- elapsed time,
- speed,
- city seed,
- four line states,
- station levels,
- depot state,
- lifetime revenue / passengers.

A dedicated browser-save importer should be added once the Godot passenger and city models reach parity. Importing earlier would create misleading partially-compatible saves.

## Parity roadmap

### G0 — runtime foundation

Done in this milestone:

- project boot,
- camera,
- HUD,
- deterministic terrain,
- rendering split,
- native save.

### G1 — transport geometry and Bus Era shell

Done in this milestone:

- Lines 1–4,
- shared interchanges,
- Bus Depot,

- buses,
- map-first purchasing.

### G2 — exact passenger simulation

Core model done in this milestone:

- waiting matrix per origin/destination,
- physical onboard loads,
- stop dwell / boarding / travel phases,
- fare only on destination arrival,
- abandonment / station queue limits.

Still required for full G2 parity:

- visible waiting passenger objects,
- boarding / alighting visual effects,
- golden fixture comparison against the JS model for long deterministic runs.

### G3 — persistent city model

Core runtime done in this milestone:

- 15 districts from the canonical master-plan fixture,
- transport-driven district activation,
- road construction projects,
- parent-road construction dependencies,
- blocks and parcels,
- building projects,
- pressure / age-driven development,
- protected reservations carried in persistent city data,
- building height / street-facing orientation,
- incremental road / junction / building rendering.

Remaining G3 work:

- port the procedural master-plan algorithm itself so arbitrary seeds can generate their plan natively in Godot,
- add parity fixtures for multiple seeds.

### G4 — topology

Current state:

- semantic roads, graph edges and junctions are already consumed by Godot from the canonical fixture,
- parent-road dependencies are active in city construction.

Still to port algorithmically:

- road snapping,
- intersection discovery,
- semantic-road splitting,
- corridor collision,
- parent / terminal connection generation.

Until that is complete, `npm run godot:fixture` regenerates the canonical default-seed plan from the JS topology engine.

### G5 — 3D city parity

Port:

- procedural roads,
- sidewalks,
- junction meshes,
- building heights / orientation,
- construction animation,
- forest clearing,
- ambient traffic.

### G6 — save migration

- JSON export path from web version,
- v12 browser save → Godot conversion,
- cross-runtime parity fixtures.

### G7 — switch primary runtime

Only after:

```text
Godot gameplay parity
+ deterministic parity fixtures
+ acceptable performance
+ save migration verified
```

Then the Three.js runtime can be retired.


## Canonical master-plan bridge

During the migration, the browser generator remains the authoritative algorithm for creating the master plan.

The default Godot plan can be regenerated from the current JS implementation with:

```bash
npm run godot:fixture
```

This writes:

```text
godot/data/master_plan_284731.json
```

The current canonical fixture contains:

- 15 districts,
- 105 semantic roads,
- 342 routing graph edges,
- 92 real junctions,
- 108 blocks,
- 161 parcels,
- 2 protected reservations.

Godot then owns the runtime state of those objects: activation, road construction, parcels, projects and buildings.

This bridge is intentional. It lets the visual/runtime port progress without duplicating the most sensitive topology algorithm before parity tests exist.
